Agentic Consumption
What's Working, What's Next

Cambrian API Team · February 28, 2026

How to make Cambrian the default data layer for autonomous agents. Two paths: MCP + API key (live today) and x402 payments (new revenue channel). Leverage existing execution tools — don't build what already exists.

Strategy

Two paths to agent consumption

Path A: MCP + API Key

The standard path. We already have this. Agents connect with one command. API key authenticates every call.

  • Best for: Developer adoption, Claude/Cursor/IDEs
  • Auth: X-API-KEY header (existing)
  • Billing: Subscription or usage-based
  • Status: Live — 68+ tools from OpenAPI

Path B: x402 Payments

Machine-native. Agent pays per call with USDC. No subscription, no account needed. HTTP 402 → sign → retry.

  • Best for: Autonomous agents, M2M traffic
  • Auth: Wallet signature = identity + payment
  • Billing: Per-call USDC micropayments
  • Status: Requires pricing strategy

These paths are complementary. Path A is live today. Path B adds a new revenue channel for agent-native traffic.

Authentication

ERC-8128: Your wallet is your API key

How it works

Instead of the server issuing an API key, the agent signs each HTTP request with its Ethereum key. Server verifies. No credential to store, rotate, or revoke.

Built on RFC 9421 (IETF standard, ratified 2024). ERC-8128 adds Ethereum key binding: keyid = erc8128:8453:0xABC...

Why it matters

  • Same key for identity + auth + payment — one address does everything
  • No credential management — no API keys to leak or rotate
  • Replay protection built in — timestamps + nonces in signed components
  • Implementable today — RFC 9421 is ratified. Only keyid format is draft.
Authentication

ERC-8128: Wallet-signed HTTP requests

Today: API keys

Agent stores X-API-KEY: sk-abc123... in memory
↓
If key leaks: Attacker has permanent, unlimited access.

ERC-8128: Signed requests

1. Agent signs: method + path + body hash + timestamp
↓
2. Sends Signature + Signature-Input + Content-Digest
↓
3. Server ecrecover(sig) → wallet → check ERC-8004 registry

Why this is safe

Request-bound
Signature covers the exact method, path, body, and timestamp. Intercepting a GET /pools signature gives zero access to POST /trade.
Time-bounded
Signature includes a timestamp + expiry. Captured signatures become invalid within seconds.
Wallet = identity = payment
Same key signs API requests AND x402 payments. Composable with ERC-8004.
Smart account compatible
Works with EOAs (ecrecover) AND smart accounts (ERC-1271). Session keys can scope agent permissions.

ERC-8004: On-chain MCP registration

Register Cambrian MCP on-chain

Each MCP server mints an NFT. The tokenURI points to an agent card on IPFS describing the endpoint, tools, and x402 support. Agents discover servers by querying the registry.

{
  "type": "eip-8004#registration-v1",
  "name": "Cambrian DeFi Data",
  "endpoints": [{ "name": "MCP",
    "endpoint": "https://api.cambrian.org/mcp",
    "mcpTools": ["get_token_price", ...] }],
  "x402Support": true,
  "supportedTrust": ["reputation"]
}

What this enables

  • Autonomous discovery — agents query registry, find MCP servers, connect without human setup
  • 24K+ agents already registered — live on Ethereum mainnet since Jan 2026
  • Reputation registry — on-chain feedback helps agents choose reliable providers
  • Multi-chain — deployed on Base, Arbitrum, Optimism, BSC

The MCP Marketplace already generates ERC-8004 registration JSON for every listed server.

Infrastructure

Enabling payments for agents

Privy Server Wallets

App-controlled wallets via API. Keys split via Shamir, reconstituted in TEEs. Sub-200ms. Policy engine: allowlisted recipients, max amounts, quorums. Now owned by Stripe — integrates with Bridge stablecoins.

Coinbase AgentKit

Wallet + framework + on-ramp. Base-native. Gasless via paymasters. MCP-compatible via getMcpTools(). Ships a dedicated Payments MCP for wallet/stablecoin ops.

Smart Accounts (ERC-4337)

Session keys: owner authorizes an ephemeral key scoped to contracts, amounts, time. Agent signs autonomously within constraints. Paymasters sponsor gas — agents need USDC, not ETH.

x402 Facilitator

Coinbase + Cloudflare launching x402 Foundation. Facilitator verifies payment signatures, settles on-chain. Free tier: 1K tx/month. Our x402 gateway at deep42.cambrian.network uses this model.

Agent Strategy

BYOK agent: users pay their own LLM costs

The approach

Instead of building a cheap, limited agent — offer a higher quality agent where users pay for their own Claude usage (BYOK). 10% platform markup only.

  • Full Claude Code reasoning — not a cheaper substitute
  • Cambrian MCP pre-connected — data + execution adaptors out of the box
  • Per-wallet context — skills improve from each user's patterns
  • TEE-backed — AMD SEV-SNP protects user secrets and keys

Focus

What not to build

Be the Bloomberg terminal, not the trading desk.

Swap / bridge / lending execution
Commoditizing rapidly. Solana Agent Kit, base-mcp, Jupiter, Aerodrome are free and maintained.
Custom wallet infrastructure
Privy (75M+ accounts, now Stripe-owned), Coinbase AgentKit, Crossmint solve this. Use them.
Agent orchestration framework
Claude, LangChain, OpenAI Agents SDK handle orchestration. Let them compose your tools.
Cheap limited agents
Instead, offer high-quality agents where users pay for their own Claude usage. Quality wins over cost.

The industry is converging: Google UCP, Worldpay, and PayPal all launched MCP-compatible payment specs in Jan 2026. The infrastructure exists — focus on the data.
