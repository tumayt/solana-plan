Modular vaults. Configurable risk.

Overview

01

Where Euler sits

Euler V2 sits between Aave and Morpho. Modular vaults connected by a shared interoperability layer.

  • Anyone can create vaults permissionlessly
  • Vaults can use any other vault as collateral
  • Risk is isolated per vault by default
Core Layer

EVC

Ethereum Vault Connector. Standardizes how vaults talk to each other. Handles auth, batching, deferred solvency checks.

↑ built on top
Vault Builder

EVK

Euler Vault Kit. ERC-4626 credit vaults with borrowing on top. One token per vault, fully configurable at creation.

Terminology

02

Vault, market, pair

Three levels of abstraction. "Vault" in Euler isn't what "market" means in Morpho.

Vault

Single lending pool for one asset (e.g., a USDC vault). Closest equivalent to a Morpho market.

Market

Cluster of vaults grouped under the same governor (e.g., "Frontier Falcon", "Euler Prime").

Pair

Relationship between two vaults, one borrowing from the other. Where LTV, LLTV, and oracle live.

Example

Same USDC collateral vault: 94% Max LTV when paired with USDT debt vault, 90% when paired with USDf. Risk parameters live on the pair, not the collateral.

Ethereum Vault Connector

03

The interoperability layer

Vaults don't talk to each other directly. They talk through the EVC.

Collateral vault

Deposits used as collateral for borrowing in other vaults. Multiple can be enabled per account.

Controller vault

The vault a user enables to borrow from. One controller per account at a time. All enabled collateral is under its control.

Batching

Bundle multiple operations across vaults into one transaction. All succeed or all fail. Critical for complex multi-step strategies.

Deferred checks

Solvency checks deferred to end of batch. Constraints can be temporarily violated mid-batch as long as everything is healthy at the end.

Euler Vault Kit

04

ERC-4626 vaults with borrowing on top

One token per vault. Fully configurable at creation.

Vault components

Underlying asset

The ERC-20 token the vault holds. Always one per vault.

EVault

Main contract. Tracks deposits and borrows, checks position health, executes liquidations.

Price oracle

Connects to external pricing systems for real-time collateral and debt values.

IRM

Kink model or Adaptive Curve. Sets borrowing rates based on market conditions to balance supply and demand.

ProtocolConfig

Global config. Controls where fees go and how they are split.

DToken

Read-only ERC-20 for debt. Makes borrow amounts visible in block explorers.

Advanced configuration

The same collateral vault can be assigned different LTVs and price oracles by each borrower vault. Same collateral source, different risk parameters per loan.

Vault types

05

Main vault types

Who manages the vault determines how risk parameters change over time.

Governed

Managed by KYB-verified risk curators. Best for passive lenders. Active parameter management.

Ungoverned

No governor, fixed parameters. Users manage their own risk. Two subtypes depending on whether the accepted collateral carries governance exposure.

Liquidations

06

More sophisticated than most protocols

Reverse Dutch auction

Discount grows with how unhealthy the position is. HF=0.98 → 2% bonus. Worse position, bigger incentive. No over-penalty for small violations.

LTV ramping

Governors reduce LTV gradually instead of instantly. Positions become unhealthy over time, getting liquidated at minimal loss. Avoids cascade events.

Bad debt socialization

Default: losses shared across all depositors when collateral can't cover obligations. Governors can disable.

Oracles

07

Adapter + router per vault

Oracle-agnostic. Each vault composes its own pricing from modular pieces.

Adapters

Translate a specific feed (Chainlink, Pyth, RedStone) into Euler's standard format. Each adapter is immutable and ungoverned.

Router

What the vault actually connects to. Routes price queries to the right adapter per asset pair. Can be governed or made immutable.

Push vs Pull

Push (Chainlink): updated externally, can go stale silently. Pull (Pyth): consumer-updated, 2–3 min validity, lower gas. Different risk profiles.

EulerEarn & DAO Markets

08

Passive yield layer on top of EVK

Same architecture as Morpho MetaVaults.

Forked from Morpho MetaVaults

Deposits one asset, allocates across up to 30 EVK strategies via supply/withdraw queues.

Same four-role structure

Owner, curator, allocator, guardian.

Performance fee

Up to 50% of net positive yield. Minted as vault shares. Identical to Morpho V1.

Loss handling

Tracked via lostAssets. Share price stays stable. Last withdrawers absorb bad debt, same as Morpho V1.1.

Key takeaways

09

What to remember

01

EVC is the core innovation

Vaults use each other as collateral through a standardized interoperability layer.

02

Rehypothecation is opt-in

More capital efficient than Morpho's isolated model but adds contagion risk depending on cluster setup. Simple pairs behave like Morpho markets.

03

Liquidations

Reverse Dutch auction, discount scales with how unhealthy the position is. Small violations get small penalties.

04

EulerEarn is a Morpho MetaVault fork

Same four-role structure, same fee model, same loss handling behavior.

Every call through the EVC

The user interacts with the EVC, not the vault directly. CallWithContext wraps every call with caller, onBehalfOfAccount, and target. This is what enables sub-account accounting.

Where funds sit

Each vault is its own ERC-4626 contract and holds its own ERC-20 directly. No singleton like Morpho, no aToken-style logic split like Aave.

Annex

A2

A few mechanics worth understanding

Sub-accounts and onBehalfOfAccount
How it works

Each wallet has 256 virtual sub-accounts. Deposits and debts can be assigned to any of them via the EVC's onBehalfOfAccount field. In TX2, the USDC collateral and cbBTC debt live at sub-account ...Adf, but the borrowed cbBTC goes to the main wallet (...Ade).

Deferred status checks
VaultStatusCheck

"Is this vault healthy?" Checks vault-level invariants (caps, accounting). One per affected vault.

AccountStatusCheck

"Is this borrower solvent?" Checks collateral covers debt for a specific sub-account. Only fires if a controller is enabled.

Routing: Aave vs Morpho vs Euler
Aave: User → Pool Proxy → aToken contract
Morpho: User → Router → Vault → Morpho main contract
Euler: User → EVC → Vault (context-wrapped)
