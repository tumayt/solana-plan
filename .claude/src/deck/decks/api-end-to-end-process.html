Cambrian API
End-to-End Process

Our objective: Start measuring then optimizing how long it takes us to go from syncing a new chain to serving new endpoints

Evaluation

How do we evaluate supporting new chains and protocols?

  • Customer demand & willingness to pay
    Where should we focus our work? Adding a new chain vs. adding a new protocol vs. expanding existing support for existing protocols. Would our customers pay for it?
  • TVL
    Chain-level yield TVL, protocol-specific TVL on each chain
  • Stack fit
    Reusable work, effort to integrate, alignment with our standards. Does this require expanding them?
  • Market signals
    Reputable teams, sustained growth, liquidity, institutions deploying capital, stablecoin volume, grants
  • Costs vs. potential revenue
    Infrastructure + compute + storage + maintenance + (...) costs vs. addressable market and projected revenue
  • Competitive gaps
    Where are competitors weakest? First-to-market opportunities (e.g., curator data, Euler borrow = 0 sources on DefiLlama)

Why we started with Base

Base chosen because all 3 target protocols (Morpho, Aave V3, Euler V2) are deployed there. $5.6B yield TVL, 1,266 pools. 3 of 5 initial customers need Base first.

Ethereum & Arbitrum should be much easier — because they have less blocks and less transactions per block so it is much faster to sync.
